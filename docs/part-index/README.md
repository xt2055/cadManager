# 零件视图一期：实施入口

编写日期：2026-09-09。

本目录用于把零件视图需求交给另一个模型实现。当前只编写实施文档，尚未实现文档中的新增功能。

## 给实施模型的任务

请先完整阅读 [implementation.md](./implementation.md)，再按其中第 15 节的步骤顺序实施。

必须遵守：

1. 阅读仓库根目录 `AGENTS.md`，禁止启动子代理。
2. 先执行 `git status --short`，保留已有未提交修改；不要清理不认识的文件。
3. 实施本目录规定的一期范围，不自行扩展 PDM、版本审批、相似度算法或项目 ACL。
4. 复用已有前端标题栏提取，不重写 CAD 引擎，不把后端文件名识别接口当作标题栏识别来源。
5. 每完成一个步骤，运行该步骤的验证，再进入下一步。
6. 持续更新本目录下你新建的 `progress.md`，记录完成项、修改文件、命令结果和剩余问题。
7. 如果代码与本文基线不同，先记录真实差异；不得为了套用文档而删除后续代码。
8. 不能用假接口、固定示例数据或吞掉异常来通过验收。
9. 数据库集成测试未执行时必须写“未执行”，不能写“全部通过”。
10. 只在隔离测试 schema 中创建或清理测试数据，不操作真实业务数据。

## 本次最重要的约束

- 一个零件索引公开地址对应一个附件，数据库记录按附件版本区分。
- 同一附件可以关联多个项目，不能复制索引来表达借用关系。
- 项目显示编号使用现有 `drawings.project`；内部关联及筛选使用 `drawings.id`。
- 标题栏图号、总图图号、项目编号是三个不同字段。
- 人工修正保存在索引层，不改 CAD 文件、不改正式零件版本数据。
- 所有当前查询必须匹配 `attachments.current_version_id`。
- 缺少当前版本识别结果时显示待提取，不能拿旧版本字段顶替。
- 当前系统代码的读取策略是登录后共享读取；本文一期继承该策略，**不宣称已经实现按项目成员隔离**。具体边界见主文档第 5 节。
