## 修复前审查结论与范围

修复前版本有 6 项已确认问题：上一轮的 3 项尚未修复，本轮新增 3 项。审查覆盖标题栏提取与保存、索引事务和投影、查询与关系展开、人工编辑与确认、批量提取、管理员补建以及前端详情的数据消费。已有浏览器端标题栏提取能力确实存在，本报告不将其列为缺失功能。

审查时未修改产品代码。数据库验证使用独立临时 PostgreSQL 实例及随机 schema，没有连接项目数据库。为扩大验证范围，使用 Go `-overlay` 加载临时审查用例，没有覆盖仓库测试文件。复现探针验证的是“问题确实存在”，探针执行成功不代表相关功能符合要求。

权限按实施文档已明确的“登录后共享读取，限制写入”边界审查；这不等于实现了原始需求中的项目成员 ACL。

## 已确认问题

### R1 / P2：合法保存的空数组值会使详情页计算和渲染失败（上一轮问题）

- 后端：`go/internal/titleblock/service.go:22`、`:55`。
- 前端：`vue/cad/src/features/part-index/pages/PartIndexDetailPage.vue:51`、`:352`。
- 标题栏校验允许 `fields` 和 `candidates` 为 nil；序列化后为 JSON `null`。详情接口将原始快照交给前端，前端却直接调用 `.some()` 和 `.length`。
- 复现数据一：`{"id":"model","fields":[{"key":"name","value":"","candidates":null}]}`。
- 复现数据二：`{"id":"empty","fields":null}`。
- 实测：后端 `Validate` 接受这两类数据；执行详情组件原有 computed 表达式，两者均抛出 `Cannot read properties of null (reading 'some')`。
- 影响：受影响快照的详情页不能正常展示，用户难以通过页面修正。

修复约定：

1. 明确快照数组字段的出站契约，统一输出数组，空集合输出 `[]`。
2. 兼容数据库已有的 null/缺失字段；仅修改新数据写入规则不够。
3. 前端入口归一化后再供布局选择、候选值展示和字段映射使用，避免多个组件各自做不完整防护。
4. 回归包括 `fields:null`、缺失 `fields`、`candidates:null`、缺失 `candidates`、正常空数组。要求可查看、可人工保存，不产生运行时异常。

### R2 / P2：提取后的版本切换被误报为批量成功（本轮新增）

- `vue/cad/src/services/title-block-workflow.ts:31`。
- `vue/cad/src/features/part-index/part-index.helpers.ts:88`。
- 时序：读取 v1 → 提取 v1 → 保存 v1 成功 → 当前附件切换为 v2 → 再次读取返回 v2，且 `snapshotRevision=0`。
- 工作流没有检查读回版本与开始版本是否相同；重建 helper 遇到修订号 0 直接正常返回；批量计数器据此增加成功数。
- 实测通过注入上述 IO 时序调用现有工作流、重建 helper 和串行批量函数，结果为 `succeeded=1`、`rebuilds=0`。
- 影响：当前版本仍未提取，用户却看到成功。没有发现该时序把 v1 内容写入 v2；问题是成功状态与当前版本不一致。

修复约定：

1. 保存后的读回必须校验 `versionId` 与开始版本一致；不一致应返回明确的版本冲突。
2. 提取完成路径若没有有效快照，应报错或明确记为跳过，不得统计为提取成功。
3. 批量只在版本校验和重建均成功后增加成功数。
4. 回归包含保存前切版、保存后读回前切版、同版正常完成、新版已有快照四种时序；不能只覆盖解析接口返回 409。

### R3 / P2：必填项校验错误被返回为 500（上一轮问题）

- `go/internal/partindex/normalize.go:54`。
- `go/internal/http/handlers/part_index_handler.go:296`。
- 确认时图号或名称为空，仓库返回普通 error；HTTP 层只把 `ErrInvalid` 映射为 400。
- 数据库调用及 HTTP 错误映射均已复现，最终响应为 `500 {"code":500,"data":null,"message":"零件索引操作失败"}`。
- 影响：正常表单校验被伪装成服务故障，丢失“图号和名称不能为空”的修正提示。

修复约定：

1. 使用可被 `errors.Is(err, ErrInvalid)` 识别的校验错误，同时保留具体消息。
2. HTTP 返回 400；详情页展示具体错误。前端可以提前提示，但不得替代后端校验。
3. 回归图号空、名称空、全空白、合法确认四类情况；非法确认后数据库字段、修订号和确认记录均不变。

### R4 / P2：完整字段校验接受 null，并静默转换为空字符串（上一轮问题）

- `go/internal/http/handlers/part_index_handler.go:266`。
- 当前只检查 12 个字段名称及反序列化结果；Go 对 string 字段反序列化 JSON `null` 不会报错，而会留下空字符串。
- 实测提交完整 12 项、其中 `material:null`，处理器返回 200，并将 `Material=""` 交给保存层。
- 影响：错误客户端或旧客户端提交的 null 会被当作用户主动清空，可能覆盖原材料、工艺等信息。

修复约定：

1. 逐项检查原始 JSON 值确实为字符串；null、数字、布尔、数组、对象均返回 400。
2. 明确允许空字符串 `""`；它代表有意清空，不能与 null 混同。
3. 对全部 12 项做表驱动测试，同时验证非法请求不会调用存储层。

### R5 / P2：日期归一化与 PostgreSQL 不一致，会阻断保存（本轮新增）

- `go/internal/partindex/normalize.go:61`。
- `go/internal/partindex/projector.go:151`、`:241`。
- Go `time.Parse` 接受 `0000-01-01`；当前函数把它当作有效日期，之后传给 PostgreSQL `date`。
- 实测人工保存返回 `SQLSTATE 22008: date/time field value out of range: "0000-01-01"`，事务失败。
- 详情页虽然显示无效日期提示，却允许保存，并承诺这类原文只是不参与日期筛选。当前后端不能兑现该行为。
- 同一日期投影逻辑也用于标题栏自动投影，应一并覆盖，避免识别到异常日期时连快照保存都失败。

修复约定：

1. 统一支持的日期范围，建议 `0001-01-01` 至 `9999-12-31`，并验证真实日历日期。
2. 不合法日期保留在 `drawing_date_raw`，投影的 `drawing_date` 为 NULL，不阻断草稿保存。
3. 日期筛选参数不合法时返回 400。
4. 前端与后端使用一致规则；JavaScript `Date.UTC` 对 0–99 年有特殊处理，不能直接拿它判断所有四位年份。
5. 回归年 0000、0001、0099、0100、闰日、不存在的日期、非标准原文，以及自动提取保存路径。

### R6 / P3：UUID 接受大小写，但后续按字符串比较（本轮新增）

- `go/internal/partindex/repository.go:181`、`:239`、`:306`、`:582`、`:716`。
- 参数正则接受大写十六进制字符；数据库 `uuid::text` 输出小写，部分查询和版本检查按字符串比较。
- 实测同一个关联项目 UUID：小写筛选返回 1 条，大写返回 0 条，且无参数错误。
- 静态检查发现详情附件 ID、版本字符串比较和补建游标也存在同类用法，应一起修正。
- 影响：复制或外部客户端传入等价的大写 UUID 时可能出现空结果、错误冲突，游标比较也可能不符合 UUID 的实际顺序。

修复约定：

1. 入口统一解析、规范化 UUID，或在 SQL 中使用 UUID 类型比较；不可只改一个接口。
2. 覆盖附件 ID、项目 ID、版本 ID、补建游标。
3. 回归全部使用包含 a–f 的 UUID，同时测试大写、小写和混合大小写。现有全数字 UUID 测试数据无法暴露此问题。

## 本轮实际验证

- 原有标题栏数据库测试：快照保存、索引同事务生成、重复保存幂等、多布局选择后自动字段正确、文件版本隔离。

- 一个零件关联两个项目只产生一个列表条目，包含两个项目；借用项目可筛选。
- 无活动项目关联、非零件附件、软删除附件、删除的当前版本不出现在列表。
- 相关 Go 包测试通过：`partindex`、`titleblock`、`http/handlers`；`attachment` 包无测试文件。
- 标题栏工作流及零件 helper 的 14 个 Node 测试通过。
- `npm run type-check` 通过。

### 尚不能据此宣称通过的范围

- 没有进行真实 DWG/DXF/EXB 样本的完整浏览器交互验收。
- 没有用完整历史数据升级数据库，也没有完成实施文档 DB01–DB26 全矩阵。
- 扩展数据库测试复用了现有简化 schema，不等同于生产完整约束和迁移链验证。
- 没有进行大数据量查询性能、长时间批量提取或网络断连压力测试。
- 前端空值问题通过执行组件原有 computed 表达式复现，不是完整浏览器端到端测试。
