# 上线前核心 UI / UX 审查

审查日期：2026-09-14。目标：清晰、简单，让用户知道当前位置、操作结果及下一步。

## 修复进展

已按用户确认实施下文第 1–7 项，原审查记录保留作对照：

- 创建后区分保存结果与预览生成结果；转换弹窗可进入详情、重试失败文件和恢复状态查询，成功后正确跳转。已保存项目的后续处理失败不会再次创建项目；相关资料先归档再等待预览，资料重试仅处理未成功的文件。
- 创建向导按目标步骤校验，错误定位到对应步骤与字段；移除前两步与必填规则冲突的快捷保存，统一使用“创建草稿”。
- 未保存创建内容的返回、侧栏跳转、退出登录有放弃确认；刷新/关闭有浏览器提醒，桌面窗口注册关闭保护；正常保存后的跳转不提示放弃。
- 审核意见按账号、案例、轮次和节点保存到当前会话；查图返回与组件重新加载后恢复，提交失败保留、成功清除，并增加返回本次审核的入口。
- 图纸库支持清空全部条件、保留返回时的模式/条件/展开状态/滚动位置，移除无结果的“已禁用”选项，修正搜索自动展开无法收起的问题。
- 图纸库和详情分别展示加载、失败可重试、无结果和确实不存在；所有图纸详情子页保持图纸库导航高亮。

验证：新增 `npm run test:ux`，11 组实际 Vue 组件逻辑与模板回归通过；现有审核回归 9 项、架构检查、类型检查和生产构建均通过。测试中的网络与业务写入使用替身，未提交真实图纸或审核；登录后的浏览器全流程及打包桌面窗口关闭动作尚未人工验证。构建仍有 CAD 依赖的资源路径、浏览器兼容外置模块与大分包提示。

本次未调整后端与权限配置；第 8 项及后续信息组织建议不在本次七项修复范围内。

## 范围与结论

优先检查工作台、图纸检索、创建、详情导航、送审与审核。实际启动本地前端并查看了登录页；登录后的结论来自组件、路由、状态存储及事件处理代码审查，尚未完成登录后的浏览器操作复现。本报告不代表完整 UI 验收，不评价后端可靠性。本轮未修改业务代码、提交业务数据或执行真实审核。

核心问题集中在操作连续性：创建向导晚一步校验、转换失败后没有清晰出口、跨页面时输入和检索条件丢失。建议先处理这些问题，再收拢入口与文案。

值得保留的设计：工作台按设计员、审核员、管理员组织信息；审核页聚焦当前节点；上传已有失败文件重试机制；工作台已区分加载、失败和空状态，可作为其他页面的统一样式。

## 上线前优先处理

### 1. P1：创建成功与转换完成混在一起，转换异常后用户可能被困住

- 场景：项目已保存，某个文件转换失败，或读取转换状态时网络异常。
- 代码行为：项目保存后才等待转换；转换弹窗仅在全部成功时关闭。转换失败只有重试按钮，没有进入详情或关闭入口；读取状态失败直接退出轮询，弹窗仍显示，错误写入的 `createError` 没在这个弹窗中展示。重试全部成功后，重试函数也没有执行进入详情的导航，与“完成后将进入图纸详情”不符。
- 影响：用户无法判断项目是否创建成功，可能刷新或重复创建。后台处理时间被误认为当前操作未完成。
- 最小优化：保存成功就显示“图纸已创建，预览生成中”，允许进入详情；详情展示每个文件的处理状态和重试入口。将保存失败、预览生成失败明确区分。若保留弹窗，至少补充退出、网络失败提示、恢复查询及重试成功后的导航。
- 验收：覆盖全部成功、单文件失败、轮询断网、重试成功四种情况。每种情况下均能确认项目已保存与否，并有可继续操作的入口。
- 证据：`vue/cad/src/features/drawings/pages/DrawingCreatePage.vue:263`、`:292`、`:948`、`:1007`。

### 2. P1：创建向导校验晚一步，快捷保存承诺与必填规则不一致

- 场景：不填写第二步基础信息，点击“下一步”；或第一步点击“跳过后续，直接保存”。
- 代码行为：`validateUpTo` 用目标步骤判断需要校验什么，但 `nextStep` 传当前步骤，点击步骤导航时又传 `step - 1`。第二步可以带空值进入第三步，直到离开第三步才报第二步错误；第三步必填属性也可以跳过，到最终保存才报错。最终保存只弹提示，不定位到错误字段。
- 影响：用户在当前页找不到被要求填写的内容，步骤打勾也不代表已填写完整。第一步的直接保存还可能被后续尚未看到的必填属性阻止。
- 最小优化：统一按“即将进入的步骤”校验；错误留在对应步骤、字段下显示并聚焦。必填信息完成后才出现“创建草稿”，上传和补充资料明确标为可选。
- 验收：第二步空值不能进入第三步；第三步必填属性为空不能进入第四步；点击任意后续步骤行为一致；任何保存失败均定位到对应字段。
- 证据：`vue/cad/src/features/drawings/pages/DrawingCreatePage.vue:110`、`:697`、`:1258`、`:1362`。

### 3. P1：创建中离开页面没有保护，填写和选文件的工作可能丢失

- 场景：填写项目、选择多个图纸后，误点返回、取消或左侧其他入口。
- 代码行为：表单和待选文件保存在页面局部状态；`handleCancel` 直接清理待上传会话并返回图纸库。页面及全局路由未发现针对未保存内容的离开拦截。
- 最小优化：无修改时直接离开；有未保存内容时提供“继续编辑 / 放弃创建”。所有离开入口使用同一判断。文本草稿可按业务需要保存；本地文件恢复能力必须准确说明，不能暗示刷新后一定能保留。
- 验收：返回、取消、侧栏切换、浏览器返回均不会无提示丢失填写内容；刷新或关闭有明确提醒；成功创建后的正常跳转不被拦截。
- 证据：`vue/cad/src/features/drawings/pages/DrawingCreatePage.vue:36`、`:177`、`:679`；`vue/cad/src/router/guards/auth.guard.ts`、`permission.guard.ts`。

### 4. P1：审核意见与查图分离，正常查阅流程可能清空已输入的意见

- 场景：审核员先写一段意见，再点击“查阅图纸”或变更文件“浏览 / 变更前后对比”，之后返回审核。
- 代码行为：意见仅存于 `ReviewWorkspacePanel` 的局部 `ref`。查图通过路由离开审核页，外层没有页面缓存；组件重新进入时又根据待办节点将意见初始化为空。未发现意见草稿持久化或离开提醒。
- 最小优化：以账号、审核案例、轮次和节点保存临时意见，成功提交后清除；提供明确的“返回本次审核”。后续可考虑在审核页内开预览面板，减少来回跳转。
- 验收：输入意见后依次查图、比对、返回，意见仍在；切换图纸、节点、轮次或账号不会串用旧意见。
- 证据：`vue/cad/src/features/reviews/components/ReviewWorkspacePanel.vue:43`、`:139`、`:147`；`vue/cad/src/features/reviews/components/ChangeReviewEvidence.vue:56`；`vue/cad/src/features/reviews/pages/ReviewCenterPage.vue:5`。

## 高价值小改动

### 5. P2：图纸库筛选反馈不完整，返回列表又要重新查找

- “重置所有筛选”只清除业务属性，不清搜索词、状态或图纸类型；只有属性被选时才出现该按钮。
- 状态下拉包含“已禁用”，但总图和零件结果都提前排除已禁用，因此选择后必定无结果。
- 搜索、模式、展开项均为页面局部状态，打开详情后返回会重新初始化，无法继续原来的查找上下文。
- 搜索命中零件会自动展开所属项目，但收起逻辑只更改手动展开集合，命中条件仍强制展开；箭头状态也只看手动集合，容易出现箭头与内容不一致。
- 建议：统一汇总有效筛选，提供真正的“清空全部”；业务规则既然隐藏禁用项目，就不在此提供该选项；保存检索模式、条件及列表位置；允许用户收起自动展开结果。
- 验收：组合搜索、属性、类型、状态后能一次复位；从零件模式打开详情再返回仍保留原检索；搜索自动展开后能手动收起。
- 证据：`vue/cad/src/features/drawings/pages/DrawingLibraryPage.vue:21`、`:82`、`:114`、`:121`、`:133`、`:178`、`:240`、`:265`。

### 6. P2：加载失败和确实没有数据显示为相同空状态

- 图纸库加载异常被吞掉，列表只判断是否有结果；初次进入详情时也只判断图纸是否存在，尚未加载就可能显示“未找到图纸”。全局短暂提示无法代替当前页面的持续错误反馈。
- 建议：统一为加载中、加载失败并可重试、无匹配结果、确实没有数据四种状态；检索无结果提供清空筛选，真正空库提供创建入口。可复用工作台已有表现。
- 验收：慢网不误报“未找到”；断网明确提示重试；清空筛选可从无结果恢复。
- 证据：`vue/cad/src/features/drawings/pages/DrawingLibraryPage.vue:146`、`:335`；`vue/cad/src/features/drawings/layouts/DrawingDetailLayout.vue:26`、`:78`；状态源已存在于 `vue/cad/src/stores/drawing.store.ts:14`。

### 7. P2：进入图纸详情后，主导航错误高亮工作台

- 主导航仅把 `drawing-library`、`drawing-create`、`drawing-detail` 判作图纸库；实际详情默认重定向到 `drawing-preview`，其他详情子页也落入默认工作台分支。
- 建议：按路由归属统一确定主导航选中项，所有图纸详情子页都保持图纸库高亮。
- 验收：图纸文件、3D 图纸、结构、审核、版本等子页选中项一致；审核中心仍正确选中图纸审核。
- 证据：`vue/cad/src/layouts/components/DesktopSidebar/SidebarNavigation.vue:49`；`vue/cad/src/router/routes.ts:93`。

### 8. P2：变更证据未加载时，可能把待本人签署误报为“还未到你”

- `canSign` 同时检查审核权限和变更证据是否已加载。证据未就绪导致它为假后，模板直接进入“还未到你”分支，即使当前责任人就是本人。
- 建议：分别表达“正在加载审核资料”“资料加载失败，请重试”“等待其他人签署”，保留现有的证据未就绪禁止签署规则。
- 验收：用当前责任人打开变更审核，慢网和资料请求失败均不会显示错误的责任人状态。
- 证据：`vue/cad/src/features/reviews/components/ReviewWorkspacePanel.vue:55`、`:280`；`vue/cad/src/features/reviews/components/ChangeReviewEvidence.vue:31`。

## 以清晰简单为目标的信息组织建议

以下是设计建议，尚需在真实业务数据和常用窗口尺寸下验证，不作为已复现缺陷。

1. **创建只保留一条主线。** 建议呈现为“导入图纸（可跳过）→ 核对信息与必填属性 → 创建草稿”；3D 模型和资料可以创建后补充。若本次不调整步骤数量，也应统一主操作为“下一步 / 创建草稿”，减少“保存并创建、跳过后续直接保存、先立项稍后补传”等同义按钮。
2. **图纸库让搜索先出现。** 当前所有业务属性筛选放在搜索和结果之前，并带有“必填项”标签，容易让用户误以为查询也必须填写。默认突出搜索，更多属性收进“更多筛选”；查询页移除必填标记；“已收录 N 份”不要使用随筛选变化的结果数，筛选后改为“找到 N 份”。
3. **详情页突出下一步。** 当前十二个子入口已经分组，可保留分类基础；常用的文件、结构、审核保持直接可达，低频记录考虑折叠。页头根据角色和状态提示“补充图纸 / 提交审核 / 查看进度 / 申请变更”，减少让用户自己猜操作入口。最终顺序应以设计员和审核员的实际使用频率决定。
4. **统一业务词。** “分叉继承”可改为“基于已有图纸新建”；“冻结提交”可用“本轮送审版本”，细节放在帮助说明中。同一种对象避免在不同页面混用图纸、项目、档案而不说明关系。
5. **保持工作台现有方向。** 不再增加统计卡和装饰，优先保证“我的待办、最近图纸、创建”能一眼找到。

## 建议上线验收顺序

1. 设计员：创建空白草稿 → 校验必填信息 → 离开保护 → 创建成功。
2. 设计员：多文件导入 → 部分转换失败 → 进入详情 → 重试成功；另测轮询断网。
3. 查图：组合检索 → 打开详情 → 返回原结果 → 清空所有条件；另测零件自动展开与收起。
4. 审核员：待办进入 → 填写意见 → 查图 / 对比 → 返回 → 意见仍在 → 在明确授权的测试案例中验证提交。
5. 刷新详情、慢网、断网：分别看到正确的加载、失败和空状态。

完成上述路径后，再用业务常用窗口尺寸检查表格横向滚动、底部按钮可见性和字级。当前没有登录后的截图与实际操作结果，不对这些视觉项目做通过判断。
