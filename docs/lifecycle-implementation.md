# 图号资料、变更审核与专利管理实现说明

本次按原有图号继续管理，不引入计划号。保留已有总图、零件、备料表、工艺及老图纸导入入口。

## 用户入口

- 图号详情 → **资料档案**：客户沟通、确认图、技术要求、工艺及其他材料，可填写多级目录；上传后只能追加新原件，不能覆盖历史资料。
- 图号详情 → **变更工单**：申请人上传依据，管理员审批并指定设计员，设计员保存修改、结束编辑后提交完整审核。
- 图号详情 → **生命周期**：首次审核、变更原因、审批动作、每轮实际修改、当轮证明材料、变更前/后原件、各审核节点及正式发布档案。
- 左侧 → **专利管理**：登记专利、关联图号、指定负责人、录入有依据的缴费和到期日期、上传证书及缴费凭证、登记缴费与下一期提醒、查阅办理历史。

## 流程规则

1. 初次完整审核通过后自动存档为正式在用版本。
2. 管理员批准变更申请只授予修改权限，不代替技术审核。审批前必须归档本次变更依据。
3. 只能由指定设计员提交变更成果，每次提交复制完整审核流程，所有可执行节点重新签署；不继承上轮通过结论。
4. 提交时固定文件版本和证明材料清单。审核工作台提供本轮原件，正式图纸库继续显示在用版本。
5. 最后一个节点通过时，在同一数据库事务内完成审核、切换文件版本、同步自有零件修订、更新签署记录及正式发布快照。发布前复核原版本基线。
6. 任一节点驳回则返回设计修改，下一次提交建立新轮次。终止工单关闭对应审核并保留历史。
7. 历史原件、正式版本、提交内容和签署结论受数据库保护，工作版本不再自动清除。旧版本并非删除后替换，而是切换在用指针。
8. 借用零件的文件变更须在源图号发起；当前图号只授权自有零件和所属文件。

## 专利提醒

- 缴费期限和权利期限独立保存，日期依据必填，不依据“每几年”猜算期限。
- 提前提醒天数可配置为 1～365 天，默认 90 天。缺失日期也会显示待完善提示。
- 后台启动时及每小时登记提醒；按提前、一个月内、一周内、次日、当天、逾期阶段去重。客户端每五分钟及重新切回窗口刷新提示。
- 管理员看到全部待关注专利，其他用户的侧栏提示其负责的专利。办理页保留系统提醒历史。
- 缴费登记要求本专利的原件凭证、实际日期、金额币种、下一期期限和依据，防止重复使用同一凭证登记。保存后不再按上一期日期提示未缴费。
- 当前实现为应用内提醒和办理档案；不执行付款，不发送短信或邮件，也不将登记期限当作官方实时法律状态。

## 部署信息

数据库迁移：`go/database/migrations/000041_lifecycle_and_patents.sql`，由现有嵌入式迁移机制加载。

旧版尚待管理员验收、且未关联完整审核的工单会恢复到执行状态，原提交保留为历史，并记录升级原因，允许设计员重新提交完整审核。已完成历史工单不回退。

资料原件存储在 **配置的 StorageRoot 后追加 `-documents` 的独立目录**，避免被旧 CAD 文件清理任务处理。部署和备份时应同时包含数据库、CAD 存储目录和该资料目录。单次资料上传总请求上限为 100 MB。

本轮遵照用户要求未运行测试、构建或数据库迁移；已进行代码编写及 Go 格式化。功能尚未在运行环境验收。
